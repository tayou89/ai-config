# What the commit wrapper does

Read from the `git-commit` skill, section 6, when the wrapper refuses or behaves unexpectedly.

The wrapper:
1. Refuses a checkout whose `.agent-workflow.json` is missing or unreadable, before anything else (FAIL exit 11; ask the user which mode the repository uses and record it, as the skill's section 1 says). In a linked worktree, when a Claude session commits, it refuses unless the folder's owner record (`scripts/folder_owner.py`) names this session (FAIL exit 12, naming the owner, or saying how to claim a worktree with no owner yet), and refuses while the folder hook has recorded calls there it could not match to the folder's owner, one gap per call, unless `--accept-gaps` is given, which the hook asks the user about (FAIL exit 13); a gap the owner's own call left after it took the folder does not count, since the owner's writes there pass anyway; it then validates subject prefix + length, body line length, body line count, bullet count, internal-term ban
2. Holds this checkout's commit lock until the commit is checked, recorded, and the shared index refreshed, so a commit through this wrapper or an integration tool already running in this checkout finishes first (it prints that it is waiting; FAIL exit 10 after 30 minutes, nothing committed); a plain `git commit` takes no lock. Run it with a timeout long enough for that wait and the pre-commit check, or in the background. Without `--expect-head` it reads HEAD after the wait. With it, if HEAD is no longer that commit, it rebuilds a private index (`--private-index` or a hand-built one) on the new HEAD when the new HEAD descends from the expected one on the same branch and holds every listed file as the expected one did (not for `--amend`, an empty file list, or the shared index), and otherwise refuses (FAIL exit 6; see 6a). It refuses `--amend` unless HEAD is a commit this session made through the wrapper and on no remote-tracking branch (FAIL exit 9)
3. Prints `git log --oneline -3` for amend awareness
4. Stages exact files passed as argv (skipped with `--no-stage`)
5. Prints `git diff --cached --stat`
6. Verifies no extra files staged beyond argv (with `--no-stage`, only when files are given; FAIL exit 3)
7. Refuses a staged `.env` or credential file, or an added line holding a live-looking token, judged by `scripts/secret_files.py` (FAIL exit 5)
8. In the original checkout, in a Claude session, refuses staged lines that the session's write record does not show as its own, also when that record is missing or began late (user decision, 2026-11-24), and own lines that change or split uncommitted lines the record does not show as its own (FAIL exit 8); `--own-lines` stages each listed file as the base plus only the session's lines, and `--include-unrecorded <file>` commits that file whole after the shell guard has listed its lines and asked the user; it reads every listed file before refusing, so one refusal names them all; it commits each `--include-unrecorded` file as the dialog showed it (with `--no-stage`, as the prepared index holds it) and refuses (exit 8) one that changed after the dialog, so a retry whose files still match an approval, such as one after exit 6, is not asked again (user decision, 2026-11-16). In a linked worktree the owner commits the listed files whole, and `--own-lines` and `--include-unrecorded` only print a note (user decision, 2026-11-18)
9. Refuses a change of 200 or more lines outside documents and lock files without `--reviewed` (FAIL exit 7); a merge of one branch counts only what differs from Git's automatic merge of the two sides (`git merge-tree --write-tree`, the comparison `git show --remerge-diff` shows), a merge of several branches counts against HEAD, and a merge Git cannot redo is refused without `--reviewed` whatever its size (FAIL exit 7) and counts against HEAD with it (user decisions, 2026-11-17 and 2026-11-24)
10. Prints verification table
11. Invokes `git commit` (subprocess, hook does not re-fire) with `CLAUDE_SKILL_GIT_COMMIT=1` marker; the repository's own pre-commit hook still runs, and when `git commit` refuses because HEAD moved while that hook ran, the wrapper says so (FAIL exit 6)
12. Reads the commit `git commit` made from the HEAD reflog entry that carries the wrapper's `GIT_REFLOG_ACTION` mark and the commit's subject, not from a later HEAD read, since another session may commit the moment `git commit` returns (commands a hook runs inherit the mark, hence the subject); checks that it replaced the expected HEAD, and if HEAD moved while it started, undoes it with `git update-ref HEAD <moved> <made>`, which moves HEAD only while HEAD is still that commit (FAIL exit 6). With no reflog entry carrying the mark, it checks and records nothing (FAIL exit 1)
13. Adds that commit to this session's commit list, which `--amend` checks; the gaps step 1 checked are set aside as soon as that check passes, before the message is validated, so a retry after any later failure does not ask about them again

Exit codes: `0` success, `1` git error, `2` message validation, `3` staging mismatch, `4` usage error, `5` credential file or token staged, `6` HEAD moved since the index was built and the index cannot be rebuilt on it (a listed file changed, another branch, `--amend`, or the shared index; nothing committed), `7` large change, or a merge Git cannot redo, without `--reviewed` (nothing committed), `8` staged lines outside the session's write record, own lines tangled with uncommitted lines outside it, an `--include-unrecorded` file that changed after the shell guard's dialog, that no dialog showed, whose dialog record or approval cannot be read or kept, or that Git cannot place in a repository, or a write record that cannot be read (nothing committed), `9` `--amend` of a commit this session did not make or one already pushed (nothing committed), `10` another commit or integration held this checkout's lock for 30 minutes (nothing committed), `11` no readable `.agent-workflow.json` (nothing committed), `12` a linked worktree this session does not own, or one with no owner or an unreadable owner record (nothing committed), `13` the folder hook recorded calls there it could not match to the folder's owner and `--accept-gaps` was not given, or its gap record cannot be read (nothing committed).
